# InstaReframeX6 — 360° ReFrame for Insta360 X6 in DaVinci Resolve

ReFrame your Insta360 X6 360° footage directly in the Fusion page of DaVinci
Resolve — no Insta360 Studio, no intermediate render. The plugin uses the
**real lens calibration from your `.insv` file** (MEI model, xi calibration,
13 distortion coefficients per lens) instead of the coarse generic v360
approximation. Result: a clean, continuous world with no perspective breaks
at the lens seam.

## Features (v2.1)

- **360° ReFrame from both fisheye streams** directly in Fusion
  (FOV / Pan / Tilt / Roll as sliders)
- **⚙️ Auto-calibration**: reads the calibration automatically from a
  `.calib` file next to the front clip (generated by `tools/insv_calib.py`).
  Without a file, built-in defaults apply.
- **🧵 Seam fine-tuning**: `BackYaw` / `BackPitch` sliders correct the small
  residual offset between front and back lens exactly at the stitching line.
- **📥 Import without pre-splitting**: `scripts/import_insv.lua` splits a
  `.insv` inside Resolve (lossless), generates the calibration and imports
  both clips to V1/V2.
- **Synchronized front/back perspective** — one world, two lenses, no more
  "two worlds"
- **Correct back orientation** (180°-Y ray rotation instead of pixel mirroring)
- **4K output** (3840×2160 default) and aspect presets:
  4K UHD, 16:9, 9:16 (Reels/TikTok), 1:1, 4:5, 9:21, Custom
- **Lossless INSV→streams workflow** via ffmpeg (`-c copy`, no re-encode)

## Requirements

- DaVinci Resolve **Studio 21.x** (Fusion page). MEI/calibration runs as a
  DCTL kernel on the GPU.
- Insta360 X6 footage (`.insv`)
- ffmpeg (for the split — only needed if you use the import script)
- Python 3 (only for calibration generation — optional; the built-in
  defaults are sufficient for a standard X6)

## Installation

1. Copy `Fuses/InstaReframeX6.fuse` into one of the Fuse folders:
   - `%APPDATA%\Blackmagic Design\DaVinci Resolve\Support\Fusion\Fuses\`
   - or `C:\ProgramData\Blackmagic Design\DaVinci Resolve\Fusion\Fuses\`
2. Restart DaVinci Resolve (or click "Reload" in the Inspector after
   inserting the tool).
3. On the Fusion page you will find the tool under the **X6R** icon in the
   category `Fuses\Insta360`, or via **Shift+Space** ("InstaReframeX6").

## Usage

### Path A — Import script (recommended, no pre-split)

1. Run `scripts/import_insv.lua` in Resolve (Workspace → Scripts).
2. Choose your `.insv` file → the script splits it into
   `<folder>\insta_reframe\<name>_lens0.mp4` / `_lens1.mp4`, generates the
   `.calib` next to it and imports both clips to V1 (Back) / V2 (Front).
3. Open the Fusion comp on V2, drag the back clip into the graph as an
   additional MediaIn (drag & drop), add the Fuse via Shift+Space and wire
   it: `Front` ← MediaIn(lens1), `Back` ← MediaIn(lens0), MediaOut ← Fuse.

### Path B — Manual (streams prepared)

1. **Extract streams** (once, lossless):
   ```bash
   ffmpeg -i VID_xxxx.insv -map 0:0 -c copy lens0.mp4
   ffmpeg -i VID_xxxx.insv -map 0:1 -c copy lens1.mp4
   ```
   (Ready-made scripts: `scripts/split_insv.bat`; for auto-calibration also
   run `python tools/insv_calib.py VID_xxxx.insv` → creates `lens1.calib`
   next to the front clip.)
2. **Timeline**: place both clips on V2 (stream 1 = **Front**) and V1
   (stream 0 = **Back**).
3. **Fusion comp** on the front clip. The back clip must be dragged into the
   graph as an additional MediaIn (drag & drop).
4. **Wire**: `Front` ← MediaIn(lens1), `Back` ← MediaIn(lens0),
   MediaOut ← Fuse output.
5. **Inspector**: set FOV, Roll; choose an aspect preset. Pan/Tilt via the
   **Aim crosshair in the viewer** (or sliders).

## Parameters

| Param | Default | Description |
|---|---|---|
| FOV | 60 | Vertical field of view in degrees (15–170) |
| Aim | Center | **Drag view direction in the viewer** (mouse): X→Pan, Y→Tilt |
| Pan (Yaw) | 0 | Horizontal rotation (−180…180), optional slider |
| Tilt (Pitch) | 0 | Vertical rotation (−90…90), optional slider |
| Roll | 0 | Rotation around the view axis (−180…180) |
| BackYaw | 0 | **Seam fine-tuning**: horizontal rotation of the back lens (deg, −5…5), corrects residual offset at the stitching line |
| BackPitch | 0 | **Seam fine-tuning**: vertical rotation of the back lens (deg, −5…5) |
| Aspect | 4K UHD | Output format preset (4K/16:9/9:16/1:1/4:5/9:21/Custom) |
| OutWidth/OutHeight | 1920×1080 | Manual size (only for Aspect=Custom) |

## Auto-calibration (⚙️)

The Fuse looks for a `.calib` file **next to the front clip** (same base
name, e.g. `lens1.mp4` → `lens1.calib`) at render time. The file is created
with:

```bash
python tools/insv_calib.py VID_xxxx.insv -o lens1.calib
```

Format: simple `Key=Value` lines (`front_xi=2.45543`, `front_m0=0.999973`,
…). If no file exists, the built-in defaults apply (verified X6 values,
firmware v1.1.78).

## How does the mapping work?

For each output pixel a view ray is computed, rotated by Pan/Tilt/Roll and
projected through the **MEI projection** of the respective lens:

```
Ray → Roll/Tilt/Pan → Extrinsics (per lens, from .calib) → MEI forward → Distortion → Sample → Output
```

The lens calibration (xi=2.45543, fx≈3611, cx/cy, k1–k4, p1/p2, s1–s4 per
lens) comes from the `.insv` metadata (INFO f111/f112). The back lens is
mapped through a real 180°-Y rotation of the rays — the rear view is
therefore correct (not mirrored). The sensor roll (~89.66°) is deliberately
NOT applied (verified: it worsens the result).

## Known limitations

- **Seam/parallax artifacts on very close objects (< ~3 m)**: Insta360
  solves this with a trained AI model (not reproducible here).
- The calibration can be loaded per shot (auto-.calib); without a file the
  verified X6 standard values apply.
- In clip comps the comp format determines the display — aspect presets
  provide the image size, the project format must be chosen accordingly
  separately.
